# Radio Record Windows App

[![Build](https://github.com/goderfly/radio-record-windows-app/actions/workflows/build.yml/badge.svg)](https://github.com/goderfly/radio-record-windows-app/actions/workflows/build.yml)

Десктопный плеер радиостанций [radiorecord.ru](https://radiorecord.ru) на Electron + React + TypeScript.
В интерфейсе приложение называется коротко — **RECORD**.

Готовый установщик: [Releases](https://github.com/goderfly/radio-record-windows-app/releases) (скачивается без входа) или [Artifacts последнего прогона сборки](https://github.com/goderfly/radio-record-windows-app/actions/workflows/build.yml) (нужен вход в GitHub).

## Возможности

- **Плеер** — два синхронных `audio`-элемента дают мягкий кроссфейд при переключении каналов, плюс буферизация, авто-переподключение и ручной ретрай.
- **Каталог** — 117 каналов, поиск с нечётким сопоставлением (fuzzy), фильтр по 19 жанрам, сортировка по названию/популярности. Жанровый чип на плитке — кнопка: клик по нему сужает сетку до этого жанра, повторный клик снимает фильтр, и всё это синхронизируется с сайдбаром.
- **Избранное и недавние** — хранятся локально, синхронизируются с трей-меню.
- **История эфира** — что играет прямо сейчас плюс 60 последних треков с обложками и ссылкой на Яндекс Музыку. Строку ленты можно кликнуть: трек переключается и подсвечивается. Кнопки «влево/вправо» и медиа-клавиши листают эту ленту внутри канала: поток-то эфирный, перемотать звук нельзя, поэтому листается отображение, а чип «В эфире — вернуться» возвращает к текущей песне.
- **Качество потока** — 32/64/96 кбит/с (реальные битрейты берутся из имени файла, а не из легаси-меток API).
- **Таймер сна** — 15/30/60/90 минут или до конца трека.
- **Системная интеграция** — трей с меню, медиа-клавиши, глобальные хоткеи, автозапуск, свернуть в трей по закрытию, запоминание размеров окна.
- **Тёмная и светлая темы** — на токенах, снятых с CSS самого сайта. Обе проходят WCAG AA: smoke-тест обходит каждый видимый текстовый блок в обеих темах и требует ≥ 4.5:1 (≥ 3:1 для крупного текста).

### Горячие клавиши

| Действие | Клавиши |
| --- | --- |
| Play / пауза | `Space`, `MediaPlayPause` |
| Предыдущая / следующая песня в эфире | `←` / `→`, `MediaPreviousTrack` / `MediaNextTrack` |
| Предыдущий / следующий канал | `Alt` + `←` / `→` |
| Поиск | `/` |
| Раскрытый плеер | `Shift` + `F` |
| Открыть трек в Яндекс Музыке | `Enter` на строке истории эфира |

## Команды

```bash
npm install

npm run dev        # запуск с HMR
npm run build      # сборка в out/
npm run typecheck  # tsc для main и renderer
npm run icons      # генерация PNG-иконок и трей-иконок
npm run catalog    # обновить снапшот каталога из API
npm run smoke      # e2e-проверка UI и аудио (нужна сборка)
npm run dist       # сборка установщика через electron-builder
```

### Smoke-тест

Прогоняет настоящее окно приложения: проверяет вёрстку, контраст текста в обеих темах, загрузку обложек, отсутствие «утекших» слоёв, клики мышью по карточкам и строке истории эфира, проигрывание выбранного трека, тянет реальные байты AAC через прокси, отдачу M4A-фрагмента и отказ прокси хосту вне allowlist, делает скриншоты.

```bash
$env:RECORD_MINI_SMOKE="C:\Windows\Temp\rm-smoke"; npm run smoke
```

Результат — 52 проверки, файлы `report.json`, `layout.txt` (ASCII-карта панелей), `smoke.png` и `smoke-light.png`.

## Сборка .exe в CI

`.github/workflows/build.yml` гоняет `windows-latest` на каждый пуш в `main`, на pull request и вручную (`workflow_dispatch`):

1. `npm ci` с кэшем загрузок Electron и electron-builder;
2. `node tools/check-icons.mjs` — проверка закоммиченных иконок (жёсткий gate: битая иконка уехала бы в таскбар);
3. `npm run icons` с `continue-on-error` — растеризация знака идёт через Chromium, у раннера нет GPU, а закоммиченные PNG всё равно источник истины;
4. `npm run typecheck` и `electron-vite build`;
5. `electron-builder --win` — NSIS-установщик и portable-сборка;
6. `actions/upload-artifact` — оба `.exe` появляются на странице Artifacts прогона.

Тег вида `v1.0.0` дополнительно публикует те же `.exe` в GitHub Release. Сборки не подписаны, поэтому Windows SmartScreen предупредит при первом запуске.

Иконки лежат в репозитории (`resources/*.png`, ~80 КБ) намеренно: без них сборка зависела бы от запуска Electron на раннере.

### Неочевидные решения

**Прокси потока в main.** Chromium не грузит `.aacp` с удалённого origin, а CORS-заголовков у radiorecord.ru нет. Поэтому аудио всегда идёт через локальный HTTP-сервер на `127.0.0.1`, который проксирует поток и шлёт `icy-metadata: 0`. Рендерер ретраит сам, если оборвалось соединение.

**Схема `app://` вместо `file://`.** Под `file://` документ получает непрозрачный origin, из-за чего `CSP 'self'` блокирует собственные скрипты. Кастомная схема даёт нормальный origin и позволяет включить полноценный CSP.

**Битрейт из имени файла.** Поля `stream_64/128/320` в API исторические и не соответствуют реальности — `stream_64` на самом деле отдаёт 32 кбит/с. Единственный достоверный источник — число в имени файла.

**Логотипы каналов — инлайн-SVG, а не баннеры.** API отдаёт `svg_fill`/`svg_outline` (200×200, все пути `fill="white"`). Широкие баннеры в сетке смотрелись как обрезки фото, поэтому карточка показывает сам знак канала. Разметка не вставляется в DOM как есть — она перекодируется в `data:image/svg+xml` с заменой `fill="white"` на нужный цвет: так SVG обрабатывается браузером как картинка (никакого скрипта из payload'а выполнить нельзя), а цвет подстраивается под тему. Подложка под белым знаком остаётся тёмной в обеих темах. Баннер используется только как фолбэк, если у канала нет логотипа.

**Лента эфира листается, а не перематывается.** Поток эфирный, вернуть звук на минуту назад нельзя. Поэтому «влево/вправо» двигают курсор по массиву истории: `history[0]` — то, что играет сейчас, дальше по индексу — прошлое. Звук при этом продолжает идти в эфире, а в интерфейсе это помечено серой точкой и чипом «В эфире — вернуться», чтобы не выдавать архив за текущий трек. Когда лента обновляется (окончилась песня, все треки сдвинулись на один индекс), курсор держит ту же песню по `id`, а не слетает на эфир.

**Выбранный трек из ленты играет фрагментом.** Эфирный поток не перемотать, но API отдаёт для каждого трека `listenUrl` — 30-секундный отрывок (AAC в M4A, ~1 МБ), он есть у 342 треков из 353. Клик по строке (или стрелка) грузит этот фрагмент вместо потока, поэтому в плеере слышно именно то, что выбрали. Дальше в движке файл, а не поток: ни HLS-фолбэка, ни реконнекта с backoff, обработчик `ended` — это «фрагмент дозвучал», а не обрыв. По его окончанию приложение само возвращается в эфир, чтобы звук не пропадал молча на невидимой границе; в плеере строка помечена чипом «Фрагмент», а чип кнопки читается «Фрагмент — в эфир». Треки без `listenUrl` (их единицы) двигают курсор, но звука не дают — честнее, чем молча оставить играть эфир.

**Прокси превью не превращается в открытый релей.** Рендерер сам присылает URL для `/preview`, поэтому main проверяет схему (`https:`) и хост по белому списку CDN Apple (`audio-ssl.itunes.apple.com`, `is*-ssl.mzstatic.com`) и отвечает `403` на всё остальное. `Range` пробрасывается, иначе Chromium не сможет искать внутри клипа.

**Плитка целиком кликабельна, поэтому вложенный чип глушит событие дважды.** Плитка — `article` с `role="button"` и своим `onClick`/`onKeyDown`, а внутри неё живут настоящие кнопки: сердечко избранного и жанровый чип. Клик по чипу обязан вызвать `stopPropagation()`, иначе он всплывёт на плитку и запустит канал; `onKeyDown` тоже глушится, иначе `Enter`/`Space` сработают дважды — один раз как кнопка чипа, второй как активация плитки. Известный компромисс: у роли `button` в ARIA презентационные потомки, поэтому скринридер может не добраться до вложенного чипа — сознательно оставлено в пользу требования «кликабельна целиком», а `title` описывает действие текстом.

**Смена фильтра сбрасывает прокрутку.** Новая сетка обычно намного короче предыдущей, и без сброса пользователь остался бы за последней карточкой. Эффект в `StationGrid` реагирует на `view`, `query` и `genreFilter`.

**Dev-сервер слушает только IPv4.** По умолчанию Vite берёт `host: "localhost"`, и на Windows это IPv6-`::1`. Electron при этом резолвит `localhost` в `127.0.0.1` и падает с `ERR_CONNECTION_REFUSED` — при живом сервере, который только что напечатал баннер `dev server running`. В `electron.vite.config.ts` адрес зафиксирован: `server: { host: "127.0.0.1", port: 5173, strictPort: true }`. `strictPort` нужен, чтобы занятый порт давал понятную ошибку, а не тихо уезжал на 5174.

**HTTPS принудительно.** API местами отдаёт `http://` для обложек. Они апгрейдятся до `https://` на границе API-слоя, а не ослаблением `img-src` в CSP.

**Ссылка на трек ведёт в Яндекс Музыку.** В эфирном API есть только `itunesUrl` — идентификатора в каталоге Яндекса там нет, поэтому deep link собрать не из чего. Рабочий способ — их публичный поиск: `https://music.yandex.ru/search?text=<артист> <название>`. Он открывает нужный трек и в приложении, если оно установлено, и на сайте. Знак взят из их собственного `favicon.svg` (`resources/yandex-music.svg`) вместе с тёмной подложкой: жёлтый глиф без неё нечитаем на светлой теме.

**Иконка приложения и знак в заголовке.** `resources/record-mark.svg` — знак Record, вырезанный из вордмарка с сайта (`viewBox 80.2 5.2 139.1 41.4`, `fill="currentColor"`). В заголовке окна он рисуется инлайн-компонентом `RecordMark`, поэтому красится текущим цветом и не требует второго запроса. Иконки (`icon.png`, трей-иконки) генерируются растеризацией этого знака через Chromium и canvas — `tools/gen-icons.mjs`; `tools/check-icons.mjs` потом проверяет результат: центрирование, скруглённые углы, градиент и контраст середины плитки (3.31:1, выше порога WCAG 3:1 для графики).

**Контраст тёмной темы.** Собственные `--n-400`/`#7a7a7a` сайта дают 4.3:1 на фоне страницы и 3.6:1 на «утопленном» — то есть весь вспомогательный текст (описания карточек, жанровые чипы, счётчики сайдбара, переключатель сортировки) был ниже AA. Семантические токены текста заданы явно: 15.5 / 10.1 / 6.2:1 в тёмной и 14.4 / 6.8 / 5.3:1 в светлой. Для акцентного текста и «18+» заведены отдельные токены `--accent-text` и `--status-error-text`, потому что `#fc581f` как текст на светлом не добирает до 4.5:1.

**Прокрутка в smoke-тесте отключается намеренно.** В стилях стоит `scroll-behavior: smooth`, и в окне, которое композитор считает перекрытым, такая анимация не тикает — строка истории эфира остаётся за пределами вьюпорта и нативный клик по ней не попадает. Это артефакт тестового окна, а не приложения, поэтому проверка на время меняет `scroll-behavior` на `auto`. Заодно геометрия сетки меряется через `offsetTop`, а не `getBoundingClientRect()`: `.card:hover` поднимает плитку на 2px, и трансформация разбила бы один ряд сетки на два в замерах.

**Сторожевые проверки селекторов.** Zustand v5 сравнивает результат селектора по ссылке. `useStore((s) => s.settings?.favorites ?? [])` создаёт новый массив на каждый снапшот и загоняет React в бесконечный цикл рендера — поэтому пустые массивы берутся из общих констант (`useFavorites`, `useRecents`).

**Слои с `position: absolute` требуют `position: relative` на родителе.** Иначе фолбэк обложки «уплывает» к ближайшему позиционированному предку и заливает оранжевым всё окно. Smoke-тест ловит это сравнением DOM с реально отрисованными пикселями.
